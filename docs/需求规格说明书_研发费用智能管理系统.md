# 研发费用智能管理系统（Agent 平台）需求规格说明书

| 项目 | 内容 |
|------|------|
| 版本 | v1.0 |
| 日期 | 2026-08-26 |
| 状态 | 评审稿（本项目为个人作品，数据为演示数据） |
| 一句话定位 | 一个**能对话**的研发费用管理助手：政策问答、费用归集、风险扫描、工时填报，四位一体 |

---

## 1. 背景与问题（为什么做）

**政策背景**：国家对研发活动给予所得税**加计扣除**优惠（研发费用可在税前加计扣除，最高按 100%），高新技术企业另有认定与复核要求。政策每年调整，口径复杂。

**真实痛点**（面向中小企业的财务/研发人员）：
1. **政策难查**：加计扣除口径、辅助账、留存备查资料要求散落在多份文件里，翻找慢、易漏；
2. **归集易错**：研发费用要按 **8 类口径**（人员人工、直接投入、折旧、无形资产摊销、新产品设计费、装备调试、其他相关费用、委托研发）分别归集，人工分类错误率高；
3. **缺风险预判**：税务局（金税四期）按多个比例指标核查（如其他相关费用≤10%、研发人员占比≥5%），企业往往事后才知道踩线；
4. **工时填报繁琐**：研发人员按项目填工时，信息不全、格式乱。

**目标**：用 Agent（多智能体 + RAG）把这些高频、规则明确、查询型的工作自动化，**回答要可靠（不编造）、过程要可控（敏感数据人工审核）**。

---

## 2. 用户与场景

| 角色 | 典型问题 | 对应功能 |
|------|----------|----------|
| 财务人员 | "加计扣除比例是多少？辅助账怎么设？" | 政策问答 |
| 财务人员 | "把这笔 5 万委外费用归集一下" | 费用归集 |
| 企业高管 | "我们现在的研发费用有哪些风险？" | 风险扫描 |
| 研发人员 | "帮我填这周三在 A 项目的工时" | 工时填报 |
| 管理员 | 员工查"我的工资"类敏感问题 | 人工审核（HITL） |

---

## 3. 范围

**包含**：政策问答（知识库检索）、费用归集（8 类口径）、风险扫描（金四 6 指标）、工时填报（单条录入）、敏感查询人工审核、多轮对话记忆、检索质量保障（混合检索/重写重搜/缓存）。

**不包含**（诚实边界，一期明确不做）：
- 真实 ERP / 财务系统对接（费用数据为内置演示数据）
- 真实税务申报、账务处理（只做问答与提示，不代做账）
- 多租户权限体系、多人协作审批流
- 发票 OCR、批量导入

---

## 4. 功能需求（FR）

### FR-1 政策问答（核心）
- 1.1 基于知识库回答研发费用政策问题（加计扣除、高企、口径、辅助账、备查资料、申报流程）
- 1.2 **防幻觉（grounding）**：检索内容与问题不相关时必须拒答，不得编造
- 1.3 回答必须附**引用来源**（知识库文件名 + 片段）
- 1.4 检索不到时支持**改写重搜（CRAG）**一次
- 1.5 高频问题走缓存，毫秒级返回

### FR-2 费用归集
- 2.1 把自然语言费用描述归类到 **8 类口径**之一
- 2.2 支持列出当前费用条目（演示 ERP 数据）
- 2.3 分类结果可解释（说明归到哪类、为什么）

### FR-3 风险扫描
- 3.1 对标金四 **6 个比例指标**扫描企业研发费用数据
- 3.2 每个指标输出 **绿/黄/红** 预警与建议
- 3.3 支持列出指标含义

### FR-4 工时填报
- 4.1 把自然语言转成工时单（员工/项目/日期/时长）
- 4.2 **信息不全必须先确认，不得补造数据**
- 4.3 支持列出/更新工时记录

### FR-5 敏感查询人工审核（HITL）
- 5.1 命中敏感词（我的/个人/工资/薪资/薪酬）的查询先进入审核队列
- 5.2 管理员批准后同一问题可再次命中返回结果
- 5.3 审核状态持久化（SQLite）

### FR-6 多轮对话记忆
- 6.1 同一会话支持追问与上下文理解
- 6.2 服务重启后历史不丢失（checkpointer 持久化）
- 6.3 支持 /reset 清空会话

### FR-7 可靠性（Agent Harness）
- 7.1 所有工具调用统一包装：**超时（10s）/ 有限重试（2 次）/ 日志 / 耗时统计**
- 7.2 防死循环：递归上限 + 循环守卫（AgentLoopGuard）

### FR-8 可观测
- 8.1 全链路追踪（Langfuse，可选降级）
- 8.2 每次请求带 request_id，日志可关联

### FR-9 标准接入（MCP）
- 9.1 费用归集 / 风险扫描 / 工时填报 / 费用条目 暴露为标准 **MCP 工具**（stdio）
- 9.2 外部系统或其他 Agent 可协议调用

## 5. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
|------|------|------|
| NFR-1 | 准确性 | 相关问题时召回来源：Recall@3 ≥ 85%（实测 88%）；无关问题拒答率 100% |
| NFR-2 | 性能 | 命中缓存 < 1s；SSE 流式输出首字 < 3s（网络正常时） |
| NFR-3 | 安全 | 计算类工具禁用 eval，AST 白名单；敏感数据人工审核；无密码/密钥入库 |
| NFR-4 | 成本 | 上下文 token 预算：检索文档截断至 4000 字符；缓存准入策略控调用量 |
| NFR-5 | 可维护 | pytest 全量通过（当前 17 passed）；CI 自动跑测试；日志分级 |
| NFR-6 | 可部署 | docker-compose 一键启动（API + Chroma + Redis）；Redis 不可用自动降级 |

## 6. 验收标准（可测试）

| 编号 | 验收项 | 方法 |
|------|--------|------|
| AC-1 | 问"加计扣除比例"必须给出政策答案 + 引用来源 | 手动提问 + 检查来源 |
| AC-2 | 问"今天天气"必须拒答（无相关知识） | 手动提问，断言输出"未收录"文案 |
| AC-3 | 8 类费用归集分类正确 | pytest：classify_expense 用例 |
| AC-4 | 风险扫描输出 6 指标红黄绿 | pytest：scan_rd_risk 用例 |
| AC-5 | 工时填报信息不全时先反问，不补造 | pytest：fill_timesheet 用例 |
| AC-6 | "我的工资"类问题进入审核队列，批准后可回答 | 手动 + hitl.py 审核流 |
| AC-7 | 高频问题第二次提问命中缓存（Redis） | pytest：_cacheable 用例 |
| AC-8 | 工具超时/重试被 Harness 包装生效 | pytest：guarded_tool 用例 |
| AC-9 | MCP 工具可被 mcp 客户端列出并调用 | python mcp_server.py 握手 |
| AC-10 | pytest 全量通过、CI 绿色 | CI 流水线 |

## 7. 需求 → 功能 → 技术实现 映射表（面试故事线）

| 需求 | 功能模块 | 技术实现 |
|------|----------|----------|
| 政策难查、怕编造 | 政策问答 | LangGraph Supervisor-Worker（policy_agent）+ Chroma 混合检索（BM25+向量+RRF+重排）+ grounding 门控 + CRAG 重搜 + 引用来源 |
| 归集易错 | 费用归集 | expense_agent + classify_expense（8 类口径） |
| 缺风险预判 | 风险扫描 | risk_agent + scan_rd_risk（金四 6 指标红黄绿） |
| 工时填报繁琐 | 工时填报 | fill_agent + fill_timesheet（信息不全先确认） |
| 隐私合规 | 人工审核 | HITL（SQLite 审核队列 + hitl.py） |
| 效率 | 缓存 | Redis 缓存 + 准入策略（_cacheable） |
| 可靠 | 工具执行保障 | Agent Harness（guarded_tool：超时/重试/日志） |
| 标准化 | 能力开放 | MCP 协议接入（mcp_server.py，4 个工具） |
| 成本可控 | 上下文预算 | format_docs 截断 + 缓存准入 |
| 可追踪 | 可观测 | Langfuse + request_id |

## 8. 数据说明与诚实边界

- **费用/风险/工时数据均为演示数据**（mock ERP），仅用于功能演示，不代表真实企业数据；
- **政策库为教学整理**（data/ 三个 txt），非官方原文，生产使用前需由专业税务顾问审核并以最新政策为准；
- 本系统是**问答与提示工具**，不替代会计师事务所/税务师的专业判断。
